# WikiResPublique

**Res Publique** — свободная энциклопедия конфы. Живёт на https://wiki.respubli.cc

Создан через Telegram-бота 2026-08-30.

## Что где лежит

| Что | Где | Переживает пересборку образа |
| --- | --- | --- |
| Движок (код, стили, шаблоны) | `server.js`, `src/`, `public/` | — пересобирается |
| База: страницы, правки, аккаунты | `data/wiki.sqlite` | да, каталог примонтирован снаружи |
| Картинки статей | `media/` | да, каталог примонтирован снаружи |
| Начальное наполнение | `seed.js` | создаёт только недостающие страницы |

Смысл разделения: код меняется пересборкой, а данные и картинки к образу не привязаны.
Раньше база лежала в анонимном docker-томе и пропала бы при первой же пересборке.

## Как запускается

Образ собирается из этого каталога, контейнер поднимается с двумя монтированиями:

* `data/` → `/data` (запись, там база; `DB_FILE=/data/wiki.sqlite`)
* `media/` → `/media` (чтение, там картинки; `MEDIA_DIR=/media`)

Подводный камень: пути монтирования у `docker_run` считаются от рабочего каталога
сессии, а не от корня проекта. Из сессии, работающей в `.tg-worktrees/<n>`, источники
надо писать как `../../data` и `../../media` — иначе база уедет во временный worktree
и исчезнет вместе с ним. Проверять после запуска: `wiki.sqlite` должен появиться
в `data/` в корне проекта.

Порт внутри контейнера — `20030`, наружу он опубликован как
https://wiki.respubli.cc

## Как добавить фотографию к статье

1. Положить файл в `media/`, имя — латиницей: `media/emili-zaifert.jpg`.
2. В карточке статьи (YAML-блок в самом верху) указать путь:
   `фото: /media/emili-zaifert.jpg`.
3. Всё. Пересобирать образ и перезапускать контейнер не нужно — каталог
   примонтирован, файл виден сразу.

В карточке понимаются ключи `фото` / `изображение` / `image`; путь должен быть либо
от корня сайта (`/media/...`), либо полным `https://`-адресом.

## Как добавить или поправить статью

Через сайт: зайти под своим аккаунтом и нажать «Править». Ничего пересобирать не нужно,
правки сразу в базе и видны в [свежих правках](https://wiki.respubli.cc/changes).

Базовые страницы (заглавная, «Участники», шаблон биографии и статьи, заведённые из
репозитория) лежат в `src/content.js`. Сеялка при старте контейнера создаёт только
недостающие и никогда не трогает существующие, поэтому правка текста в репозитории
сама по себе на живую вики не попадает — её накатывает `apply.js`:

```sh
DB_FILE=data/wiki.sqlite node apply.js --all --dry-run   # посмотреть, что изменится
DB_FILE=data/wiki.sqlite node apply.js "Эмили Зайферт"   # накатить одну страницу
```

Страницу, которую после этого правили руками через сайт, `apply.js` не перезапишет:
скажет, чья была последняя правка, и остановится (обойти — `--force`).

## Карточка участника

Поля карточки — YAML-блок в самом верху страницы. Кроме `фото` и `подпись` любые ключи
выводятся строками таблицы в том порядке, в каком написаны. Поэтому порядок во всех
биографиях держим одинаковый: он задан списком `FIELD_ORDER` в `src/content.js`, и
`apply.js` предупреждает, если карточка из него выбилась или завела своё поле.
Лишние строки не нужны — поле, про которое сказать нечего, просто удаляют. Заготовка со стандартным
набором (город, социальный статус, религия, мбти, роль, интересы, цитата) —
страница [Шаблон:Биография](https://wiki.respubli.cc/wiki/Шаблон:Биография).

## Разное имя в ссылках и в самой статье

Если в списках и ссылках человек должен значиться под одним именем, а при открытии
статьи показываться под другим, страница называется первым именем, а в карточку
добавляется поле `заголовок:` со вторым. Оно не выводится строкой карточки — только
заменяет заголовок статьи, шапку карточки и заголовок вкладки.

## Локальный запуск

```sh
npm ci
npm run seed      # идемпотентно
npm start         # http://127.0.0.1:20020
```

Переменные: `PORT`, `DB_FILE` (по умолчанию `data/wiki.sqlite`), `MEDIA_DIR`
(по умолчанию `media/`), `INVITE_CODE` — код приглашения для регистрации.

## Кто может читать

Вики закрыта: страницы, поиск и фотографии участников видны только вошедшим,
аноним получает редирект на `/login`. Открыты лишь вход, регистрация и стили.
Вернуть открытое чтение можно переменной `PUBLIC_WIKI=1` при запуске контейнера.

## Аккаунты

Регистрация в два шага: код приглашения (`INVITE_CODE`), а затем подтверждение
администратором. Заявка создаёт учётную запись, но войти по ней нельзя, пока её не
подтвердили: на входе такой участник получает «Заявка ещё не подтверждена».

Администратор видит счётчик заявок в верхней панели и разбирает их на `/requests`:
«Подтвердить» открывает вход, «Отклонить» удаляет заявку целиком — имя снова свободно.
Снятое подтверждение обрывает и уже открытые сессии.

Исключение — самый первый живой участник: подтверждать его некому, поэтому он
регистрируется сразу, становится администратором и дальше подтверждает остальных.
Системный «Бот», от имени которого сделано начальное наполнение, на эту роль
не претендует и в заявках не показывается.
